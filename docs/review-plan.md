# План code-review: модуль `src/discount.py`

## 1. Цели ревью

- **Точность расчётов** — итоговая цена должна соответствовать бизнес-правилам
  (базовая скидка, промокоды, уровень лояльности, минимальный порог цены).
- **Защита от фрода** — исключить возможность намеренного/случайного занижения
  цены ниже допустимого порога (70% от суммы корзины).
- **Корректность применения скидок** — порядок применения SUMMER/VIP и tier-скидок
  не должен приводить к двойному или неверному начислению.

## 2. Измеримые критерии приёмки

| Критерий | Порог / правило |
|---|---|
| Магические числа | Отсутствуют; все константы (0.85, 0.90, 0.97, 0.93, 0.70, 500) вынесены в именованные константы |
| Валидация входных данных | Проверка типов и неотрицательности `cart_sum`, допустимости `tier` (0/1/2), типа `promos` (list) |
| Покрытие тестами | > 80% строк модуля `src/discount.py` |
| Линтер | flake8 — 0 ошибок |
| Граничные случаи | Есть тесты на: пустой список промокодов, cart_sum = 15000 и 15001, срабатывание нижнего порога 0.70, неизвестный промокод |

## 3. Участники и роли

| Роль | Ответственный | Зона ответственности |
|---|---|---|
| Автор кода | Разработчик микросервиса | Подготовка PR, исправление замечаний |
| Ревьюер (Tech Lead) | Владелец кода (@ВАШ_НИКНЕЙМ) | Проверка логики, критериев, аппрув |
| QA-инженер | Тестировщик | Проверка покрытия тестами, граничных случаев |
| Бизнес-аналитик | Аналитик | Подтверждение соответствия бизнес-правилам скидок |

## 4. Процесс ревью

1. Автор открывает PR в `develop`, прикладывает описание изменений и результаты локального прогона тестов.
2. CI (flake8) должен быть зелёным до начала ревью.
3. Ревьюер проверяет код по критериям из раздела 2, оставляет комментарии.
4. Автор вносит правки коммитами в ту же ветку.
5. После аппрува минимум одного владельца кода (CODEOWNERS) PR может быть смёржен.

## 5. Эскалация при спорах

| Уровень | Ситуация | Действие |
|---|---|---|
| 1 | Разногласие автор ↔ ревьюер по стилю/подходу | Обсуждение в треде PR, попытка консенсуса за 1 рабочий день |
| 2 | Не достигнут консенсус | Привлекается Tech Lead (владелец кода) как арбитр |
| 3 | Спор о бизнес-правилах (порядок скидок, порог) | Эскалация к бизнес-аналитику, решение фиксируется в PR |
| 4 | Блокирующая проблема безопасности/фрода | Немедленная эскалация к руководителю разработки, PR блокируется до решения |
